# UnifyPortfolio

Multi-exchange trading portfolio dashboard.
Exchanges: IBKR (stocks/ETFs), Hyperliquid (perps/spot), Binance (spot/perps/futures), OKX (spot/perps/futures).
Also Bybit (V5 unified account: spot + linear perps + options; TradFi/MT5 CFD account equity via /v5/asset/asset-overview — equity only, no CFD positions) and Bitget (V2 classic account: spot + USDT/USDC-M futures + Earn; Unified (UTA) accounts auto-detected via 40085 → V3 API, Earn via /api/v3/earn/savings/assets (V2 earn rejects UTA keys) + /api/v3/earn/sharkfin/assets; CFD/TradFi via /api/v3/cfd/account/fund-detail + /api/v3/cfd/trade/current-positions → assetClass 'cfd'. CFD position field names unverified — connector logs the first raw row per symbol).
Also MT5 (any broker, `exchange: "mt5"`, investor/read-only password): see MT5 below.
IBKR is currently disabled (`"enabled": false` in accounts.json) — set to true / remove the flag to re-enable.

## Architecture
- Backend: backend/ (Fastify, Node 22, TypeScript, port 8189)
- Frontend: frontend/ (Vite dev / serve.cjs prod, React 18, Tailwind, port 8188)
- Deployment: PM2 via ecosystem.config.cjs (two processes: unify-backend, unify-frontend)
- Cloudflare Tunnel: <public domain> → localhost:8188 (never write the real domain into the repo; Vite dev reads extra hosts from `ALLOWED_HOSTS`)

## Deployment
- `frontend/serve.cjs` — lightweight Node HTTP server for production: serves static files from `frontend/dist/`, proxies `/api/*` to `http://127.0.0.1:8189`, SPA fallback
- `ecosystem.config.cjs` — PM2 config with two apps: unify-backend (port 8189), unify-frontend (port 8188)
- Build: `cd backend && npm run build` then `cd frontend && npm run build`
- Deploy: `pm2 restart unify-backend unify-frontend` (NOT `pm2 restart all` — the same PM2 also runs unrelated sites and a Discord bot)

## Git workflow
- `main` = what is live. PM2 runs production from this checkout (/root/tracker/unifyportfolio), which stays on `main`: never check out another branch or build unmerged code here (`frontend/dist` is served directly, so a build here is live at once)
- `dev` = development, in its own worktree: /root/tracker/unifyportfolio-dev (`git worktree add ../unifyportfolio-dev dev`). All new work is committed there
- Test on dev: `scripts/dev.sh start` (from the dev worktree) builds it and runs PM2 apps `unify-dev-backend` / `unify-dev-frontend` on 127.0.0.1:8289 / 8288 with production's accounts.json, a snapshot copy of the history DB and Discord alerts off; `scripts/dev.sh stop` when done
- Release after testing: in the production checkout `git merge --no-ff dev`, build backend + frontend, `pm2 restart unify-backend unify-frontend`; push `main` and `dev` to origin when the user asks

## Backend key files
- backend/src/index.ts — Fastify server, API routes (/api/health, /api/portfolio, /api/history, /api/metrics, /api/trades, /api/transfers, /api/payouts, /api/portfolio/:accountId, POST /api/mcp/:token)
- backend/src/connectors/ — one file per exchange (base.ts, binance.ts, okx.ts, hyperliquid.ts, ibkr.ts, bybit.ts, bitget.ts, mt5.ts)
- backend/src/types.ts — all shared TypeScript interfaces (Position, AccountSnapshot, StableBalance, OptionDetails, PortfolioResponse, ClosedTrade)
- Each AccountSnapshot carries `stables` (USDT/USDC by location: trading / funding / earn) and optional `warnings` (non-fatal sub-request failures, e.g. earn endpoint not permitted). Use `this.sticky()` (BaseConnector) for non-critical sub-requests: on failure it serves the last good result for up to 15 min (with a warning) so a transient error doesn't make equity dip or positions look closed (fake trades); `quiet=true` for products often not enabled
- Options use assetClass 'option' + `option` details; `parseOptionSymbol()` in base.ts handles OKX/Binance/Bybit symbol formats
- cache.ts: an error snapshot never overwrites last good data (error is attached instead) and never triggers trade tracking
- `MOCK=1` env forces mock data (for UI previews)
- backend/src/config.ts — loads accounts.json
- backend/src/scheduler.ts — staggered per-exchange polling, creates connectors, calls cacheSet
- backend/src/cache.ts — in-memory TTL cache (stale-while-revalidate), also triggers trade tracking on each cacheSet
- backend/src/history.ts — 30s in-memory ring buffer (25k points) + long-term points persisted every 30 min to SQLite (backend/src/db.ts, node:sqlite, file data/history.db, gitignored; override with HISTORY_DB). Sampler waits until all accounts reported before recording; an account still missing after 3 min is carried forward at its last recorded equity (never dropped from the total). Sharpe uses session 30s samples; drawdown/period changes use persisted + session series. Curve backfill (read-time, stored rows untouched): before an account's first sample its estimated equity (backfill.ts, else its first recorded equity) is added to the total; before the first recorded sample, hourly synthetic points (`est`, total scope only) come from the estimates once every account has one — `/api/history` flags them with `backfilledBefore`, EquityChart draws them grey with a footnote; accounts.json `historyBackfill: [{accountId, before (ISO/unix, server is UTC), amount, note}]` adds funds that existed before a wallet type was tracked (to the account and total before `before`). Only for tracking changes — real gains/deposits stay. Each point also stores `off` = per-account earn + funding stables (SQLite column `off`, added via ALTER TABLE; old rows lack it). `/api/history?scope=trading` returns equity − off (raw, no transit lift; points recorded before `off` existed use the earliest recorded `off` map as an estimate, flagged by `estimatedBefore` in the response and a footnote in the chart) — EquityChart's 总权益 / 交易账户 toggle (localStorage `unify.chartScope`)
- backend/src/backfill.ts — pre-history equity estimates, per account anchored at its first recorded sample: venue account-value history where a connector implements `fetchEquityHistory()` (Hyperliquid `portfolio`: allTime weekly, month/week/day finer; shifted to meet the anchor), else walked back E(t) = E0 − Σ(closed-trade PnL + stablecoin deposits − withdrawals incl. fee + MT5 balance ops) after t. Ignores unrealized PnL at t, funding not in trade PnL, earn interest and non-stablecoin transfers (checked vs HL's own history: within ~$100 when only stables moved; HL also moved HYPE, hence native there). Coverage markers in SQLite table `meta` (`cover:trades|flows:<id>` = ms from which history is complete): trades set by `tradesObserveVenue(…, since)` (first query 90 d), flows by a one-time deep read in scheduler.ts (`deepFlows`, 90 d in 7-day windows, `fetchFlows(since, until)`); MT5 coverage = its first deal query (90 d, in memory; mt5bridge returns `balanceOps` = symbol-less deals). Synthetic points start at the latest coverage start of all accounts (≈ 90 d before the first deploy of this)
- backend/src/mcp.ts — read-only MCP server (Streamable HTTP, stateless, @modelcontextprotocol/sdk) at POST /api/mcp/<token>, token = accounts.json `mcp.token` (≥ 16 chars; no token → 404). Reachable through the public tunnel (frontend proxies /api/*), so the token is the only access control. Tools: get_portfolio, get_positions, get_closed_trades, get_trade_stats (group by category / instrument / account / side / weekday / hour / day / holding_time, tz), get_equity_history, get_performance, get_transfers. Trades / positions carry `tvSymbol` (TradingView EXCHANGE:TICKER hint: BYBIT:/BINANCE:/BITGET:xxx.P, OKX:BASEQUOTE.P, HYPERLIQUID:COINUSDC.P, MT5 → OANDA:XAUUSD / PEPPERSTONE:NAS100…) for use with the TradingView MCP. Must never return credentials, the MT5 login/server or addresses. Registered in Claude Code (user scope) as `unify-portfolio` via http://127.0.0.1:8189/api/mcp/<token>
- backend/src/transfers.ts — internal-transfer bridging. Each connector implements `fetchFlows(since)` (stablecoin deposits/withdrawals; verified live on Binance/OKX/Bybit/Bitget UTA/Hyperliquid), polled together with fetch() in scheduler.ts. A withdrawal is paired with a deposit at another tracked account (txId, else coin + amount within fee tolerance, ≤48h); the total is lifted by the in-transit amount between the *observed* debit and credit. Unpaired withdrawals to a known own address (any address we've received deposits at, or the HL wallet) count as in transit ≤24h, otherwise external. Raw equity is persisted; the adjustment is applied when history/metrics are read (so later pairings fix the past curve). Flows persist in SQLite table fund_flows. Sender mapping: accounts.json `transferSources: {"0x…": accountId}` (keep addresses out of the repo) marks deposits whose on-chain sender (`FundFlow.from`; Binance via deposit/hisrec includeSource=true) is that account's payout address as internal transfers from it — for MT5, which reports no withdrawals. Bridge runs from the deposit's venue time, or from the start of history if the source account was neither tracked nor estimated (backfill.ts) at that time (its auto-backfill is then the post-withdrawal balance). Per-account history stays raw. accounts.json `payoutAddresses: ["0x…"]` (user's own cash-out addresses, keep out of the repo): withdrawals there are never paired as internal transfers, stay external outflows on the curve, carry `payout: true` in /api/transfers and are listed by /api/payouts
- Funding: perps carry `fundingPnl` (since open, + received / − paid), `fundingRate`, `fundingIntervalH`, `nextFundingTime`, `nextFunding` (est. next payment = −side × notional × rate, via `applyFunding()` in base.ts; public rates cached 60s by `cachedPublic()`). Since-open sources: Bybit = sum of SETTLEMENT rows in /v5/account/transaction-log after max(createdTime, last flat entry) — in-memory ledger, 30d back-fill, refreshed every 5 min (verified = curRealisedPnl); HL = −cumFunding.sinceOpen; OKX = position fundingFee; Binance/Bitget = rate + next only (no since-open)
- backend/src/trades.ts — closed trades, persisted in SQLite (table `trades`), served all at once by /api/trades (frontend filters by period). MT5: exact trades from the broker deal history (`tradesObserveMt5`, called by the MT5 connector; bridge input `dealsSince`, 90 d on the first poll then 3 d): one trade per closing deal, net of commission + swap (Exness deal times are UTC); entry from the opening deals, else the open position's price seen while polling. Crypto venues: `connector.fetchClosedTrades(since)` polled every 5 min by scheduler.ts (first 20 s after start; window from `tradesSince()`: 90 d on first run, then from 2 d before the newest stored venue trade, then rolling 3 d) → `tradesObserveVenue` upserts by stable id; the account's inferred trades are dropped and inference stops for it. Sources (all verified live 2026-11-25): Bybit /v5/position/closed-pnl linear + option (≤ 7 d per query; closedPnl net of open/close fees); Binance REALIZED_PNL income locates closes → /fapi/v1/userTrades per symbol-week, closing fills grouped per order, entry = exit − pnl ÷ qty (reconciles exactly with the income total), stable-coin commission only; options /eapi/v1/userTrades realizedProfit + fee (exercise not included); OKX /api/v5/account/positions-history (id = posId, upserted; coin-margined PnL × close price, options × index); Hyperliquid userFillsByTime (closing fills grouped per coin + oid; flips count only the closed part); Bitget v2 classic / v3 unified history-position (V3 shape unverified — accepts several field spellings, logs the first raw row). Every trade has `category`: `xau` (gold incl. gold-backed tokens XAUT/PAXG; other commodities / FX would land here too), `stock` (stocks, ETFs and index contracts — NAS100, USTEC, US500, XYZ100…), `crypto`, `option`; from venue metadata — Bybit symbolType, Binance underlyingType (+ subType TradFi / Pre-IPO), OKX instCategory (3 stocks, 4/5 commodities/FX), HIP-3 dex prefix — with gold names overriding coin tags, else `guessCategory()` in backend/src/categories.ts (MT5 + fallback; bare SPX is the SPX6900 coin on crypto venues, so only US500/SPX500 count as the index). Rows stored as `commodity` are read as `xau`. `entryTime` / `durationSeconds` are null where the venue record has no open time. Fallback inference (`source: 'inferred'`, exit = last polled price, no fees) for accounts without venue history: positions aggregated per symbol + side, CFD PnL scaled by units per lot
- mtapi quirk: `Deal.Type` holds the entry (0 in / 1 out) and `Deal.Entry` the direction (0 buy / 1 sell) — swapped vs. their names; mt5bridge reads them crosswise
- accounts.json — multi-account credentials (gitignored); accounts with placeholder creds ("YOUR_...") or `"enabled": false` are skipped at startup

## MT5
- `mt5bridge/` — tiny Go helper (`mt5snap`, built on github.com/voorz/mtapi, pinned in go.mod). Build: `cd mt5bridge && CGO_ENABLED=0 go build -trimpath -ldflags="-s -w" -o bin/mt5snap .` (bin/ is gitignored; override path with `MT5SNAP_BIN`)
- backend/src/connectors/mt5.ts spawns it once per poll (`mt5PollIntervalSeconds`, default 60): credentials go over stdin, it logs in fresh (long MT5 web sessions freeze position data on some brokers), prints a USD JSON snapshot and exits. Never trades — keep it that way. Privacy: the page is public behind the tunnel — the MT5 account number and server name must never reach the API/page (CfdAccountState.name is just 'MT5' and is not rendered for mt5)
- Docker: backend/Dockerfile does not build or ship mt5snap yet — MT5 works under PM2 only
- accounts.json entry: `{"id","exchange":"mt5","label","credentials":{"login","password","server","host?"},"marginCallLevel?","stopOutLevel?"}` — call/stop-out levels aren't exposed by the protocol, set them per account if you want the buffer tiles
- Account balance (excl. floating PnL and credit) is reported as a USDT `trading` stable (USD ≈ USDT, same as Bitget CFD), so it counts in the stables totals
- Snapshot errors shown on the page are fixed messages (publicError in mt5.ts); raw mtapi text can quote the server name and only goes to the server log
- Output → `AccountSnapshot.cfd[0]` + positions with assetClass 'cfd' (rendered in CfdPanel). Notional = lots × contract size × price, converted via symbol-name currencies (non-pair symbols like US30 assumed USD-quoted). If the server reports margin 0 (Exness), margin = Σ notional ÷ leverage, flagged `marginEstimated` (shown with ≈). USC (cent) accounts are ÷100. Positions carry `sl`/`tp` (null = unset) and `tpPnl`/`slPnl` = Δprice × lots × contract size → USD at the current FX rate, excl. swap/commission

## Alerts
- backend/src/alerts.ts — CFD margin-level alerts to a Discord webhook (`alerts.discordWebhook` + `alerts.marginLevels`, default [150,100,80], in accounts.json). Fires when an account drops into a worse tier (lowest tier pings @here); improving needs +5 pts past the line (hysteresis); one all-clear when back above the top line. Called from scheduler after cacheSet; state in memory (restart re-alerts an account already below a line); a failed webhook send rolls the tier back so the next poll retries. MT5 Exness margin is estimated (notional ÷ leverage), so its margin level is too

## Rules
- Never add order placement code
- All API keys are read-only
- IBKR uses Flex Query HTTP polling (not OAuth, not TWS)
- Keep each connector isolated; errors in one must not affect others
- Only persistence: SQLite equity history (30-min points) + fund_flows (deposit/withdrawal records for transfer bridging) + closed trades + meta (backfill coverage markers). Snapshot cache and open-position tracking stay in memory (reset on restart)
- Frontend port: 8188, Backend port: 8189 (do NOT change these; the dev test instance uses 8288 / 8289 on loopback)
- USDT ≈ USD for display purposes
